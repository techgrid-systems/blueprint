Step-by-Step Implementation & Configuration Guides

Select a functional tier below to view verbatim technical deployment instructions, PowerShell installation commands, and clustering configurations.

Tier 1: Active Directory & Core Services Deployment (`TGS-DC-01` & `TGS-DC-02`)

Your Domain Controllers provide core authentication, DNS name resolution, and Group Policy replication.

1. Promote Primary Domain Controller (`TGS-DC-01`)

  • Install Active Directory Domain Services (AD DS) and DNS Server roles.
  • Promote the server to establish a new forest root domain (e.g., tgs.local).

2. Promote Secondary Domain Controller (`TGS-DC-02`)

  • Install AD DS and DNS roles via PowerShell or Server Manager.
  • Promote the server as an additional domain controller to the existing tgs.local domain.

3. Verify SYSVOL Replication Health

Windows Server uses DFS Replication (DFSR) for SYSVOL sync. Confirm health on both nodes:

# PowerShell Verification Command
Get-DfsrState -ComputerName "TGS-DC-01", "TGS-DC-02"

Check Event Viewer under DFS Replication logs for Event ID 4602 and 4614.

Tier 2: DFS Shared Data Tier (`TGS-FS-01`, `TGS-FS-02`, `TGS-FS-03`)

The three file servers utilize a DFS Namespace backed by DFS Replication to provide fault tolerance and automatic referral failover for RDS profiles and company data.

Step 1: Install Roles Across All 3 File Servers

Execute on TGS-FS-01, TGS-FS-02, and TGS-FS-03:

Install-WindowsFeature FS-FileServer, RSAT-DFS-Mgmt-Con, FS-DFS-Namespace, FS-DFS-Replication -IncludeManagementTools

Step 2: Create Identical Local Folder Paths

On each node, build the baseline directory structure: C:\Shares\CompanyData and C:\Shares\Profiles.

Step 3: Configure DFS Multipurpose Replication Group

  • Open DFS Management Console (dfsmgmt.msc).
  • Right-click Replication → New Replication Group → Multipurpose Replication Group.
  • Add all three file hosts (TGS-FS-01, TGS-FS-02, TGS-FS-03).
  • Select Full Mesh Topology and set continuous bandwidth schedule.

Step 4: Configure Domain DFS Namespace (DFS-N)

Build domain-based namespace: \\tgs.local\corporate. Add local folder targets from all 3 hosts and enable referral ordering.

Tier 3: Remote Access & Security (`TGS-GW-01`, `TGS-GW-02`, `TGS-JMP-01`)

Acts as the perimeter security barrier and strict administrative access layer.

RD Gateway Clustering (`TGS-GW-01` & `TGS-GW-02`)

  1. Install Remote Desktop Gateway role on both nodes.
  2. Import a unified SSL SAN / Wildcard certificate (e.g., *.tgs.local).
  3. Configure Network Load Balancing (NLB) or DNS round-robin pointing rdg.tgs.local to both node IPs.
  4. Configure identical RD CAP (Authorization) and RD RAP (Resource) policies across both gateways.

Management Jump Box Configuration (`TGS-JMP-01`)

Acts as the single administrative bastion host. Workstations are prohibited from connecting directly to internal server subnets. Admins must tunnel through RD Gateway to TGS-JMP-01 before launching administrative tools.

Tier 4: RDS Session Host Farm (`TGS-RDS-01`, `TGS-RDS-02`, `TGS-RDS-03`)

Delivers application compute and desktop sessions, dynamically balanced across three hosts.

1. Install Session Host Role

Deploy Remote Desktop Session Host role across all three computing nodes.

2. Configure Session Collection & Load Balancing

Group all three nodes into a single RD Session Collection. Set relative weightings to evenly balance incoming user sessions.

3. Profile Storage Mapping (FSLogix / UPD)

Set user profile disk storage path to your DFS namespace:

\\tgs.local\corporate\Profiles

Tier 5: SQL High Availability Cluster (`TGS-SQL-01` & `TGS-SQL-02`)

Provides high-availability database performance for line-of-business applications.

1. Prerequisites & Windows Failover Cluster (WSFC)

Join both nodes to domain, install Failover Clustering feature, and pass Cluster Validation wizard.

2. SQL Failover Cluster Instance (FCI) or Always On

Install SQL Server as a Failover Cluster Instance on TGS-SQL-01, then add TGS-SQL-02 as an additional cluster node.

3. Application Connection Strings

Point application connection strings to Virtual Network Name TGS-SQLCluster rather than host names.
